Overview

Yalın reads UTF-8 JSON on Android, iOS and macOS. Read selected fields from a response or build an immutable tree and map its values to your own types.

Fast field reads
Pull a few values out of a large response without building a tree for it. At 1 MB, 2.7× faster than fastjson2 on Android and 7.1× faster than Foundation on the iOS simulator.
Android full trees from 16 KB up
1.3× faster than fastjson2 and 2.7× faster than Gson at 1 MB.
Fewer Android allocations
A full tree creates about half the objects fastjson2 does and a quarter of what Gson does.
Strict by default
Invalid UTF-8, bad escapes, trailing commas and control characters are rejected. Duplicate keys are rejected in trees.
Numeric types
Integers use Long on Android and Int64 in Swift when they fit. Both preserve large numeric values.
Small surface
Three entry points across platforms. The Android AAR includes R8 rules.

32-bit devices

Native code ships for 64-bit ABIs only. If your app also targets armeabi-v7a or x86, Yalın throws UnsatisfiedLinkError on those devices. Restrict the ABIs, or keep another parser as a fallback.

android {
    defaultConfig {
        ndk { abiFilters += listOf("arm64-v8a", "x86_64") }
    }
}

iOS and macOS with Swift

The Swift package uses the same Rust parser through a native XCFramework. It supports iOS 13+, macOS 10.15+ and Swift 5.9+ (Xcode 15+), including arm64 iOS devices and arm64 or x86_64 iOS simulators and Macs.

Install in Xcode

Clone the repository and build the XCFramework on a Mac with Xcode and rustup. In Xcode, choose File → Add Package Dependencies → Add Local…, select the checkout and link the Yalin library.

git clone https://github.com/0xberkay/yalin.git
cd yalin
apple/build-xcframework.sh

Read JSON in Swift

Pass Data, a String, or another ContiguousBytes value. Every call validates the whole input. Use project to read selected fields, parse for repeated lookups, or parseTree for the whole tree.

import Foundation
import Yalin

let data = Data(#"{"user":{"name":"Ada"},"items":[{"price":12.5}]}"#.utf8)
let fields = try Yalin.project(data, "user.name", "items[0].price")
let name = try fields.string(at: 0)    // "Ada"

let document = try Yalin.parse(data)
let price = try document.double("items[0].price")

let tree = try Yalin.parseTree(data)
let first = tree["items"]?[0]?["price"]?.doubleValue

Swift releases the parsed document when its last reference goes away. Documents, projections and tree values are immutable and Sendable. Typed getters return nil for missing and null values. Use kind to distinguish them.

Pick an entry point

Everything lives on dev.yalin.YalinJson. Prefer a ByteArray input, such as OkHttp's response.body.bytes(): a String has to be encoded to UTF-8 first, which costs 13–21%.

YalinJson.project(bytes, …paths) A few fields, once One native call, any number of paths. Returns a YalinProjection indexed by path order. YalinJson.parse(bytes) Many lookups, same input Parse once, query many times. Returns a YalinDocument that you must close. YalinJson.parseTree(bytes) The whole document Builds an immutable YalinValue tree of Kotlin maps and lists.

Rule of thumb. If the code reads a handful of fields from a big response, use project: it is several times faster than any tree. Use parseTree when the code walks most of the data.

Guide

project — a few fields in one call

The input is parsed, validated and queried in a single JNI call. No document is kept, so there is nothing to close. Results come back as one compact buffer and are decoded lazily: a string is only created when you read it.

import dev.yalin.YalinJson

val input = """{"user":{"name":"Ada"},"items":[{"price":12.5}]}""".encodeToByteArray()

val fields = YalinJson.project(input, "user.name", "items[0].price")
val name = fields.getString(0)    // "Ada"
val price = fields.getDouble(1)   // 12.5

YalinProjection has getString, getLong, getDouble, getBoolean and kind, each taking the index of the path you asked for, plus size.

Guide

parse — a reusable document

When you look up many things in the same input, parse it once. The document lives in native memory until you close it, so always use use {} or try/finally.

YalinJson.parse(bytes).use { doc ->
    val count = doc.getLong("meta.total") ?: 0
    val page = doc.project("items[0].id", "items[1].id")
}

parse also accepts a ByteBuffer. Only the bytes between position and limit are read and the position does not change. A direct buffer is copied natively with no intermediate array; don't modify it during the call.

Guide

parseTree — the whole tree

YalinObject is a Map<String, YalinValue> with keys in document order, and YalinArray is a List<YalinValue>, so the standard collection functions work.

import dev.yalin.*

val root = YalinJson.parseTree(bytes) as YalinObject
val items = root["items"] as YalinArray
val names = items.map { ((it as YalinObject)["name"] as YalinString).value }

parseTree also accepts a String; error offsets are still UTF-8 byte offsets. It is stricter than parse: a repeated object key throws YalinParseException with DUPLICATE_KEY.

Guide

Paths

A path is a list of segments evaluated from the root. Keys are matched after unescaping, so "a" in the document matches the path a.

PathSelects
user.nameMember name of member user
items[3].priceZero-based array index, then a member
[0].idIndex into a top-level array
matrix[1][2]Nested arrays
""The root value itself
  • Indices are decimal without leading zeros: [07] is a malformed path.
  • A key containing ., [ or ], or an empty key, cannot be addressed. Use parseTree for those.
  • With a duplicate key, paths return the first occurrence. parseTree rejects duplicates.

    Guide

    Missing, null and wrong types

    Typed getters return null both for a path that selects nothing and for a JSON null. When the difference matters, ask for the kind.

    when (fields.kind(0)) {
    YalinKind.MISSING -> { /* no such key or index */ }
    YalinKind.NULL -> { /* present, and null */ }
    else -> use(fields.getString(0))
}
    SituationResult
    Missing path or JSON nullnull
    Value of another type, including indexing an object or reading a member of an array on the wayYalinTypeException(path, expected, found)
    getLong on a fractional or out-of-range numberArithmeticException
    getDouble on a number that overflows Double (integers are fine)ArithmeticException
    Malformed pathYalinPathException(path, position)

    Guide

    Errors

    Yalın follows RFC 8259 strictly. Invalid input throws YalinParseException with an error and the UTF-8 byte offset where it was found. Nothing is thrown from native code; the error is decoded on the Kotlin side.

    try {
    YalinJson.project(bytes, "id")
} catch (e: YalinParseException) {
    log("bad JSON: ${e.error} at byte ${e.offset}")
}

    Input that Gson or fastjson2 accepted leniently may fail here. That is expected: fix the producer, or catch the exception.

    Rejected

    • Trailing commas
    • Comments
    • Single quotes
    • Unquoted keys
    • NaN and other bare words
    • Invalid UTF-8
    • Control characters in strings
    • Bad escapes and lone surrogates
    • Leading zeros, 1., 1e
    • Data after the root value

    YalinParseError

    • INPUT_TOO_LARGE
    • UNEXPECTED_EOF
    • UNEXPECTED_CHARACTER
    • UNTERMINATED_STRING
    • CONTROL_CHARACTER_IN_STRING
    • INVALID_ESCAPE
    • INVALID_SURROGATE
    • INVALID_UTF8
    • INVALID_LITERAL
    • INVALID_NUMBER
    • DEPTH_LIMIT_EXCEEDED
    • TRAILING_CHARACTERS
    • DUPLICATE_KEY parseTree only

    Nesting is limited to 1024 levels and input to 4 GiB. A Rust panic or JNI failure surfaces as a plain RuntimeException.

    From Java

    All entry points are @JvmStatic, and YalinDocument is Closeable, so try-with-resources works.

    YalinProjection fields = YalinJson.project(bytes, "user.name", "items[0].price");
String name = fields.getString(0);
Double price = fields.getDouble(1);

try (YalinDocument doc = YalinJson.parse(bytes)) {
    Long total = doc.getLong("meta.total");
}

    Guide

    Memory and threads

    • Your bytes are copied. Input is copied into Rust-owned memory during the call, and no pointer into a Java array survives it. You can reuse or change the array as soon as the call returns.
    • Documents must be closed. There is no finalizer or Cleaner yet (it needs API 33), so an unclosed YalinDocument is never freed by the GC. close() is idempotent.
    • Queries are thread-safe. Several threads may query one document, and close() may race them safely: the memory is freed after the last query in flight. A query after close() throws IllegalStateException.
    • Handles, not pointers. Kotlin holds an opaque generation-tagged Long. A stale or forged handle resolves to nothing, and reusing a slot never revives an old handle.

    Internals

    How it works

    Each call crosses JNI exactly once, whatever the number of paths.

    1. 01Your appKotlin or Java hands over a ByteArray, ByteBuffer or String.
    2. 02One JNI callproject, parse or parseTree copies the input into native memory.
    3. 03UTF-8 checkThe whole input is validated with NEON before anything else.
    4. 04Structural scanQuotes, braces, colons and commas are found 64 bytes at a time with NEON or SSE2.
    5. 05TapeThe grammar is validated and the document recorded on a compact tape.
    6. 06AnswerPath queries read the tape directly. Trees go back in a compact binary form; repeated keys and short strings are reused across trees.

    Android benchmarks

    AndroidX Microbenchmark, release build, on an Infinix X6833B (Helio G99, Android 13). Gson, Moshi, kotlinx.serialization, Jackson, fastjson2 and org.json were tested. An equivalence test checks that every library returns the same result before anything is timed.

    1 MB input · median of a release run · lower is better

    Four-field results are from 23 Nov 2026. In the partial full-tree rerun that day, Yalın took 16.00 ms and allocated 75,455 objects at 1 MB. The full-tree and allocation charts compare the complete 20 Nov 2026 run.

    Against the fastest other library

    fastjson2 was the fastest competitor at every size.

    Method and caveats
    • The field-read workload is a deterministic product list. Every scenario returns the same four values: meta.total, items[0].name, items[mid].price and items[last].seller.name.
    • In the full-tree benchmark every library builds and returns its whole tree, and all trees are mapped to the same plain form and compared.
    • Gson, fastjson2 and org.json parse leniently by default; Moshi, kotlinx.serialization, Jackson and Yalın are strict.
    • kotlinx and org.json include the ByteArray → String decode, which is their usual input.
    • Clocks were not locked. Library versions: Gson 2.15.0, Moshi 1.15.2, kotlinx.serialization 1.13.0, Jackson 2.23.0, fastjson2 2.0.66.android8.
    • Full tables, an Exynos 7904 phone and the parser-only Rust numbers are in the repository's Android benchmarks and Rust benchmarks.

    Migrating from another parser

    1. Find where JSON is read and which fields the code actually uses.
    2. If only some fields are used, replace the model or tree parse with one project call that lists those paths, and build your object from the getters.
    3. If the whole structure is used, call parseTree and convert YalinObject and YalinArray to your types with small mapping functions.
    4. Keep the old library for writing JSON. Yalın has no serializer.
    5. Add a test with a real payload that compares the old and new results.
    // Gson: builds a full model to read three values
val page = gson.fromJson(body, Page::class.java)

// Yalın: one call, three paths
val f = YalinJson.project(bytes, "meta.total", "items[0].id", "items[0].title")
val page = Page(total = f.getLong(0) ?: 0, firstId = f.getLong(1), firstTitle = f.getString(2))

    mkdir -p ~/.agents/skills/yalin && curl -fsSL -o ~/.agents/skills/yalin/SKILL.md \
  https://raw.githubusercontent.com/0xberkay/yalin/main/docs/skills/yalin/SKILL.md
